# 有据 · 产品说明

版本：原型 v1，2026-10-11。项目目的：AI 产品经理求职展示。全部业务与资料为模拟；下述问题和价值是产品假设，尚未完成企业访谈或试点。

## 目标用户与任务

目标用户：B2B SaaS 售前人员、审核负责人、产品经理。

任务：客户提出能力、部署、指标和交付要求，售前需要判断哪些能够答复、哪些需要确认。答案可能散落在产品资料、更新记录和历史销售笔记中；资料之间也可能冲突。

价值假设：将要求、适用条件、证据与审核动作放在同一任务里，帮助审核人发现错误承诺与能力缺口。当前没有证明审核耗时减少或成交率提升。

## 核心流程

输入客户要求与部署方式 → 抽取需求 → 检索可访问资料 → 核验当前证据 → 保存答复草稿 → 人工逐条批准或退回 → 导出批准答复 → 能力缺口进入测试工单。

已支持：当前版本、所选部署方式的已审核资料足以确立能力。

明确不支持：当前已审核资料明确说明基础能力未提供。

待确认：无证据、仅历史资料、仅路线图、证据互相矛盾，或客户附加条件没有得到确认。找不到证据不等于明确不支持。

## 第一版需求

| 用户任务 | 已实现行为 | 验证方法 |
| --- | --- | --- |
| 录入采购要求 | 每行文字、CSV、3份预设问卷 | 表单和文件输入测试 |
| 核验能力 | 部署/版本/审核状态/角色共同限定资料 | 固定合成开发案例 |
| 查看理由 | 原文引用、资料编号和适用状态 | 引用逐字检查 |
| 处理冲突 | 冲突标记和双来源展示，结论待确认 | 香港模拟资料案例 |
| 人工审核 | 逐条批准或退回、答复编辑、审核备注与确认 | 页面及事务测试 |
| 交接能力缺口 | 审核后调用本地工单工具，重复执行同一工单 | SQLite 唯一约束测试 |
| 保留记录 | 原始答复、审核答复、事件与检查点 | 重启恢复测试 |

## 承诺与权限设计

路线图、未审核笔记和过期资料不能单独支持当前结论。角色权限先于检索打分；销售不可读取审核角色建立的内部资料任务。审核不改变系统能力状态；待确认答复须保留未确认表述，新增数值须有证据。

当前只允许批准原核验文字；实质改写须退回补充，更新资料后重新核验。审核人应逐条检查文字与证据。模拟身份用于展示流程，生产需要身份认证和服务端权限绑定。

## 指标定义与验证计划

| 指标 | 口径 | 当前状态 |
| --- | --- | --- |
| 能力结论匹配 | 实际结果与冻结案例逐项预期完全一致的案例数 / 总案例数 | 有离线合成开发结果 |
| 错误支持 | 预期不支持或待确认，却输出已支持的条目数 | 可从完整 JSON 复核 |
| 证据支持性 | 人工确认原文是否真的支持整条结论 | 尚无独立人工评分 |
| 审核耗时 | 完成同类任务的检索、修改与审批总用时 | 尚无真实用户测量 |
| 单任务成本 | 模型调用、输入/输出 Token、工具与重试记录 | 本轮模型调用 0 |

验收基于具体行为和固定案例，不预设未经测量的“准确率95%”“效率提升80%”等指标。后续使用新资料和新的验证案例，再组织目标用户试用，保留失败与修改记录。

## 后续产品选择

优先验证目标用户是否愿意在此处完成审核，再确定是否接入真实产品资料、企业登录与工单平台。语义检索和模型工具选择应通过对照评测证明收益后引入；它们不是第一版的效果声明。
